stale major-version pin, not a server bug: helix-db crate pinned as "2.0" in Cargo.toml resolves to 2.0.6, but crates.io's actual current release is 3.0.0 (published 2026-08-04) -- a breaking rewrite (route /v1/query -> /v2/query, DynamicQueryRequest -> QueryRequest, client.query().dynamic(req).send() -> client.query(req).send(), restructured wire format). A 2.0.6 client against a current server gets an empty-body error response, easy to misdiagnose as a server bug (see the now-closed and corrected https://github.com/HelixDB/helix-db/issues/1019). Fix: pin "3.0", not "2.0"; port the three DynamicQueryRequest/.dynamic() call sites to QueryRequest/client.query(req). Verified with a real write+read-back roundtrip against a live 'helix start dev' instance.
