dynamic query protocol version skew: helix-db crate 2.0.6 (crates.io) POSTs DynamicQueryRequest shapes (AddN/NWhere step variants) that the officially-latest server image ghcr.io/helixdb/helixdb:latest (v0.0.4) resets the connection on for BOTH read and write, silent (no server log line). The CLI's own TypeScript query runtime (helix query dev -e) works fine against the same instance -- only the Rust SDK's dynamic-query wire path is broken. Filed https://github.com/HelixDB/helix-db/issues/1019. Until fixed upstream, b00t-c0re-lib's HelixDBStore (irontology_bridge.rs) cannot be exercised even with a live local server; a live server alone does not mean grok ask/lfmf persistence works.
