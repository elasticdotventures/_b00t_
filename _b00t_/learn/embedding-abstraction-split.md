irontology-mcp has two independent embedding call paths that are NOT interchangeable: provider-api::ModelProvider (used by RepoIndexTool for ingestion, has FixtureProvider test double) vs retrieval::embed::EmbeddingClient (used by VectorBackend/NeumannBackend::search_vector at query time, hardcoded HTTP to EMBEDDING_ENDPOINT, not injectable/mockable). Content embedded via one is only meaningfully retrievable via cosine search using the SAME scheme. Discovered while wiring task #25 (graft node-card ingestion) — could not build a fully deterministic end-to-end ingest-then-retrieve test through NeumannBackend because of this seam; tested ingestion (repo.index -> NeumannStore) and retrieval (StoreBackedBackend/NeumannBackend graph/lexical/ontology, task #24) separately instead.
