native module naming: PyO3 .so files in Python packages must match the module name declared in pyproject.toml's [tool.maturin] module-name (here: b00t_pyverse._core, matching #[pymodule] fn _core in src/lib.rs). A prior version of this package's __init__.py imported "b00t_pyverse.b00t_pyverse" instead of "b00t_pyverse._core" — a naming mismatch, not a genuine circular-import requirement — which made the native module unloadable in every build regardless of packaging. Fixed: __init__.py's lazy _get_core() now does importlib.import_module("b00t_pyverse._core"), matching the actual built artifact. Renamed from b00t-py/b00t_py to b00t-pyverse/b00t_pyverse (PyPI rejected b00t-py/b00t_py as too similar to the pre-existing unrelated package boot-py/boot.py).
