# Phase 2.75 — GCP control node onto the tailnet, close public SSH

**Policy (operator, 2026-09-09):** any control node is ALWAYS on the tailnet;
non-tailnet SSH is disallowed and closed before a build is finalized. Public
SSH may stay open *only while actively building/testing*.

Everything below is authored; each apply step needs operator approval (the
session's classifier blocks infra mutations). Ordered so the public SSH path is
never cut before the tailnet one works.

## State

- `b00t-tf` `gcp-build-plane` already has `network_mode = "public" | "tailnet"`
  (no external IP, no Cloud Run waker, firewall → `tailnet_cidr` only in
  `tailnet`). Currently `"public"` (`_b00t_.toml` `[gcp].network_mode`).
- `nats/pyinfra/deploy_cp_node.py` now takes `--data tailscale_authkey= tailscale_tag=`
  and does `tailscale up --ssh --advertise-tags=tag:b00t-control-plane`.
- vultr1 (k0s) is already on the tailnet: `100.109.101.1` / `tag:vultr1`.
- SOCI + the k0s SPIRE agent DS are applied & verified.

## Steps

### 1. Tailscale ACL — add `tag:b00t-control-plane`

`GET https://api.tailscale.com/api/v2/tailnet/-/acl`, then add (HuJSON):

```jsonc
"tagOwners": { "tag:vultr1": ["autogroup:admin"], "tag:b00t-control-plane": ["autogroup:admin"] },
```
extend the `tcp:22` grant `dst` and the `ssh` `accept` rule `dst` from
`["tag:vultr1"]` to `["tag:vultr1", "tag:b00t-control-plane"]`. Validate via
`POST .../acl/validate`, then `POST .../acl` (send `If-Match: <etag>`).

### 2. Mint an auth key + join the control node (still over public SSH)

```sh
KEY=$(curl -s -X POST -H "Authorization: Bearer $TAILSCALE_API_KEY" -H 'Content-Type: application/json' \
  -d '{"capabilities":{"devices":{"create":{"reusable":false,"ephemeral":false,"preauthorized":true,"tags":["tag:b00t-control-plane"]}}},"expirySeconds":900}' \
  https://api.tailscale.com/api/v2/tailnet/-/keys | python3 -c 'import sys,json;print(json.load(sys.stdin)["key"])')

CP_HOST=$(cd b00t-tf && tofu output -raw gcp_control_node_external_ip) \
pyinfra nats/pyinfra/inventory_cp.py nats/pyinfra/deploy_cp_node.py \
  --data build_vm_sa_email=$(cd b00t-tf && tofu output -raw gcp_build_vm_sa_email) \
  --data tailscale_authkey="$KEY"
```

Confirm: `tailscale status | grep b00t-dstack-control` → an IP (call it `CP_TS_IP`).
SSH check: `ssh brianh@b00t-dstack-control true` (MagicDNS, tailnet).

### 3. dstack kubernetes backend — now the SSH path exists

```sh
ssh root@100.109.101.1 'k0s kubeconfig admin' \
  | sed -E 's#(server: https://)[^:/]+#\1100.109.101.1#' > /tmp/b00t-node.kubeconfig

CP_HOST=b00t-dstack-control \
pyinfra nats/pyinfra/inventory_cp.py nats/pyinfra/deploy_cp_node.py \
  --data build_vm_sa_email=$(cd b00t-tf && tofu output -raw gcp_build_vm_sa_email) \
  --data k0s_kubeconfig=/tmp/b00t-node.kubeconfig \
  --data k0s_proxy_jump_host=100.109.101.1
```

### 4. Flip to tailnet mode (drops the external IP + tightens the firewall)

Set `_b00t_.toml` `[gcp].network_mode = "tailnet"`, then `just gcp-apply`
(`b00t-tf`). ⚠️ only after step 2 proves tailnet SSH works — this removes the
public SSH path and the Cloud Run waker. Update the operator's dstack CLI
project URL to `http://b00t-dstack-control:3000` (no more waker URL).

### 5. Close-out (release gate)

- Verify no GCP firewall rule allows `:22` from `0.0.0.0/0` on the build-plane
  VPC (tailnet mode's `ssh_sources = [tailnet_cidr]` handles this — confirm).
- `tailscale status` — control node + vultr1 both present, tagged.
- A `dstack apply -f dev-env/k0s-ci-test.task.yaml` run schedules on k0s and
  reaches the pod via `proxy_jump`.
